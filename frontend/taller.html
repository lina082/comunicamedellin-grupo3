Modelo de Datos Cassandra (Query-First Modeling)

presencia Q1

CREATE TABLE presencia (
  usuario_id text,
  nombre text,
  comuna text,
  estado text,
  last_seen timestamp,
  PRIMARY KEY ((usuario_id))
);

Partition Key directa sobre usuario_id. Acceso y actualización en $O(1)$ (< 2 ms).

historial_usuario Q2, Q3

CREATE TABLE historial_usuario (
  usuario_id text,
  enviado_en timestamp,
  alerta_id uuid,
  titulo text,
  severidad text,
  zona text,
  PRIMARY KEY ((usuario_id), enviado_en)
) WITH CLUSTERING ORDER BY (enviado_en DESC);

Clustering Order en disco por enviado_en DESC: lecturas secuenciales contiguas.

presencia_por_zona Q4

CREATE TABLE presencia_por_zona (
  zona text,
  estado text,
  usuario_id text,
  nombre text,
  PRIMARY KEY ((zona), estado, usuario_id)
);

Tabla desnormalizada donde zona es la Partition Key, eliminando scans globales.

estado_entrega Q5

CREATE TABLE estado_entrega (
  alerta_id uuid,
  bucket int,
  usuario_id text,
  estado text,
  PRIMARY KEY ((alerta_id, bucket), usuario_id)
);

Clave compuesta ((alerta_id, bucket)) con 32 buckets para evitar hotspots de 100k filas.
